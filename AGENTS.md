# AGENTS.md

## Project

Website built as an **Astro static site generator** using **TypeScript**. The purpose is to track a Pokémon tournament. `pkm` = Pokémon.

## Current state

Scaffolded with the Astro minimal template (no git commits yet). No content collections configured yet — `src/content/` and `src/content.config.ts` don't exist until added.

## UI architecture

The site uses a Ceefax/teletext style UI.

- Global theme (fonts, Ceefax color variables, base reset) lives in `src/styles/ceefax.css` — imported once by the layout.
- Every page renders through `src/layouts/CeefaxLayout.astro` (props: `title`, `pageNumber`, `subtitle`, `nav`). It provides the header bar, nav row, content grid, ticker footer, and CRT scanline overlay. If `nav` is omitted it defaults to the site-wide page list. The layout pins the header/nav/footer to the viewport (`.ceefax` is `height: 100dvh; overflow: hidden`); page content scrolls inside `.ceefax-scroll`, and `ceefax-nav.ts` resets that scroller to the top on `astro:page-load`.
- Site-wide page numbers live in `src/data/navigation.ts` (`PAGES`, `ALL_PAGES`, `PageLink`): 100 HOME, 200 RULES, 300 STANDINGS, 301 HEAD TO HEAD, 400 TRAINERS, 500 GAMES, 600 TROPHY, 700 AWARDS, 800 HOMETOWNS, 900 HELP. Individual trainers are 401–410, game weeks are 501–509, and award pages are 701–710 (all generated from data). `ALL_PAGES` is the ordered arrow-key nav sequence and feeds the help directory.
- Keyboard navigation lives in `src/scripts/ceefax-nav.ts`, bootstrapped by the layout from serialized `data-ceefax-*` attributes on `<body>`: number keys enter a 3-digit page code, arrows step through `ALL_PAGES`, `h`/`?` open `/help`. On touch devices a horizontal swipe flips pages too: left swipe = next, right swipe = previous (same `step()` as the arrows), guarded by a 64px threshold and a 1.5× horizontal-dominance check so vertical scrolling isn't hijacked. `ceefax-nav.ts` keeps a single `keydown` listener plus `touchstart`/`touchend` listeners and reads per-page data from a window store (`ceefaxNavState`); it refreshes that store on Astro's `astro:page-load` event (dispatched on `document`, not `window`), so it keeps working across view transitions. The page-number box (`#ceefax-pagebox`, top right of the header) is clickable: clicking it swaps in a `type="tel"`/`inputmode="numeric"` input (`#ceefax-page-code-input`) so mobile gets a numeric keypad; 3 digits auto-navigate, Enter resolves, Escape/blur cancels. Delegated document listeners + a `deactivatePageBox()` reset on `astro:page-load` keep it alive across SPA navigation (the header persists via `transition:animate="none"`).
- Page navigation uses Astro view transitions (`<ClientRouter />` in the layout head). The header, nav row, and footer use `transition:animate="none"` so they stay visible (instant content swap, no fade) during navigation; the CRT overlay uses `transition:persist`. The clock span in `CeefaxHeader` is `transition:persist` so its interval survives page changes. Navigation from `ceefax-nav.ts` goes through `astro:transitions/client`'s `navigate()` (SPA) with a `location.assign` fallback. Scripts are NOT re-run across navigations (Astro dedups them), so per-page init happens on `astro:page-load` rather than `data-astro-rerun` (which strips `type="module"` from bundled scripts and double-executes inline ones).
- Player data lives in `src/data/players.ts` (`Player` interface, `PLAYERS` array of 10, `findPlayer(number)`). Trainer detail pages are generated by `src/pages/trainers/[number].astro` from this data.
- Week fixtures live in `src/data/matches.ts` (`Match`, `Week`, `WEEKS` array of 9, `weekFor(number)`). Matches reference players by number; a match has optional `wins1`/`wins2` (battles won — all three games are always played; battle count breaks ties) that render as a score when set, otherwise `VS`. The games index is `src/pages/games/index.astro` (500) and week pages are generated by `src/pages/games/[week].astro` (501–509), each listing its 5 matches.
- Trainer sprites live in `src/data/trainer-sprites.ts` (`TrainerSprite` interface, `TRAINER_SPRITES`, `spriteFor(number)`): 16×16 pixel maps where `.` = transparent and other chars map to a per-player palette (`B` = black outline, `K` = yellow skin, `H` = hair, `O` = outfit). Every row must be exactly 16 chars. Five base shapes exist (HAT, HAIR, LONG, BEARD, FEMALE — the latter used by player 10). `TrainerSprite` (in `src/components/ceefax/`) renders them as a CSS grid of square pixels; it's placed below the trainer name heading on `[number].astro`.
- Reusable UI pieces live in `src/components/ceefax/`: `CeefaxBlock` (colored content block: `title`, `color`, optional `number`), `CeefaxHeading` (`text`, `color`, `level`), `TrainerSprite` (`number`), `PageDirectory` (a numbered link list fed by `PageLink[]`), `TournamentGraphic` (homepage Pokéball wordmark), `CeefaxHeader`, `CeefaxFooter`, `TrophySprite` (28×22 pixel-art golden trophy from `src/data/trophy.ts`, shown on `/trophy` under a "CHAMPION" nameplate), `PixelArt` (generic sprite grid fed a `PixelArt` object: `sprite`, optional `size`). Award sprites live in `src/data/awards.ts` (`Award`, `AWARDS` array of 10, `awardFor(number)`) — 16×16 maps for each end-of-season award. `/awards` (700) is the directory of award cards; `/awards/{number}` (701–710) renders each award's sprite, description, and TBD winner under a nameplate, with prev/next nav centered on 700.
- The hometown map lives on `/map` (800 HOMETOWNS). `src/data/hometown-map.ts` exports `HOMETOWN_MAP` (a 48×28 `PixelArt` terrain grid: `W` water, `L` land, `F` forest, `M` mountain, `S` snow, `D` desert) and `HOMETOWN_MARKERS` (10 `{ playerNumber, col, row }` entries). `src/pages/map.astro` renders the map via `PixelArt` and overlays one linked numbered marker per trainer (absolutely positioned by grid %, linking to `/trainers/{number}`), plus a legend listing trainer → hometown.
- Colors come from the `--ceefax-*` CSS variables (cyan, yellow, magenta, red, green, blue, white, black).
- The layout's content area is a responsive grid; a page can drop blocks/headings straight into the default slot. Use `grid-column: 1 / -1` for a full-width item.

## Commands

- `npm run dev` — local dev server
- `npm run build` — static build to `dist/`
- `npm run preview` — preview the production build

## Conventions

- Astro SSG mode with TypeScript; prefer `.astro` + `.ts` over `.js`. TypeScript is set to `strict` (`tsconfig.json` extends `astro/tsconfigs/strict`).
- `astro.config.mjs` sets `output: 'static'` (the Astro default) and will host content collections once configured.
- Content (notes) live under `src/content/` with Zod schemas in `src/content.config.ts`.
- `src/content/` markdown files are treated as data; don't hand-edit generated `dist/` output.
